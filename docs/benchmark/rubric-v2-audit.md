# Benchmark rubric v2 audit

This audit separates answer defects from checks that no longer match the evidence or the customer requirements. It defines replacement contracts for the integration work; it is not a new benchmark result or a human approval.

The saved [run 42020759881](run-42020759881/README.md) remains **22 passes, 18 failures and 2 pending outcomes across 42 executions**. Its answers, facts, cards, judge receipts and scores remain historical evidence. The [canonical draft](../Question-benchmark/benchmark_draft.md) remains unchanged and unapproved by Jason. Its SHA-256 is `62098867c412942326997b292999c7208b1b7ec00652a2b8657c210f71921fe5`.

## Evidence examined

- Saved run: [report](run-42020759881/report.json), [executions](run-42020759881/executions.jsonl), [compiled cases](run-42020759881/cases.json), and its README.
- Original expected answers: `docs/Question-benchmark/benchmark_draft.md`.
- Evaluation behavior: `backend/evaluation/benchmark.py` and `scripts/judge_benchmark.py`.
- App evidence contracts: `backend/app/tools.py` and `backend/app/chat.py`.

The old rule scorer treats most required phrases literally, excludes citation markers from answer-value matching, prohibits Undetermined markers on ordinary answer targets, and makes any unmet prerequisite override rule status. The judge receives returned facts but no separate attachment inventory. These choices explain several failures below. The latest customer requirement puts routine weight failures, detailed verification, omissions and manual-review requirements in Debug. It does not permit an answer to claim a complete match when the reconstruction is partial.

## Reporting and verification boundary

Version and fingerprint the replacement rubric separately from the original draft. Judge cache identity must include the revised contract and attachment evidence; old scores cannot be reused as if the judge saw the new payload. Any replay of saved answers is an offline diagnostic, not a fresh app benchmark. A fresh two-pass run must use unchanged code/data/settings between passes and retain responses, facts, cards, independent judgments, model settings, latency and usage. Report behavioral success and prerequisite coverage separately, with no fabricated human spot-checks or engineering approval.

This audit used only lightweight source/capture inspection. It ran no model APIs, builds, CAD regeneration, browsers or heavy verification, and changed only this new audit document.
